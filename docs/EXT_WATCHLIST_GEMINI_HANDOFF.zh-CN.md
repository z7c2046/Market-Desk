## 5. 分组模型、迁移与保存

采用版本化数据结构，例如 `market-desk-watchlist-v2`，包含：

- `version: 2`；`groups: [{id, name, symbolIds, collapsed, order}]`。
- 独立证券字典：稳定内部 symbol ID、展示代码、名称；providerSymbol 在服务端适配器中映射。
- 全局去重证券集合，与多组成员关系分开；同一股票允许属于多个组，但源订阅仅一次。
- 用户偏好：当前组、分组 / 全部模式、排序字段、方向、EXT 模式、自动重排、面板展开状态。

要求：

1. 支持建组、重命名、删除、移动组顺序、折叠；股票可添加到组、移出组、移动到另一组或加入多个组。
2. 删除组默认把仅存在于该组的股票移入“未分组”，避免连带丢失全部自选；全局移除股票是独立操作。提供一次撤销。
3. 首次迁移保留旧数组，写入新结构成功后才启用新版本；旧 key 不直接删除。加载必须幂等，损坏 JSON 不覆盖可恢复的数据。
4. Notion 手动导入继续可用，先导入未分组；不将本地组同步写入长桥或其他外部账户。
5. 提供 JSON 导入 / 导出本地分组备份，校验大小、结构、代码和重复项；文案经 Vue 文本绑定展示，不使用 v-html。
6. 首版保留 30 个不同代码的现有限额，分组不重复计数。实际订阅上限低于应用上限时明确提示，不能静默漏订阅。将限额集中配置，后续有需要再提高。

## 6. 分时段数据与涨跌幅：必须明确基准

将 `regular`、`pre`、`post`、`overnight` 分开存储，不能用一个 lastPrice 字段互相覆盖。

每个报价至少包含：`price`、`priceType`（trade / bid / ask / midpoint / indicative / barClose）、`sourceTime`、`receivedAt`、`sessionId`、`tradeDate`、`provider`、`feed`、`coverage`、`delayStatus`、`status`。引用收盘价还需 `referenceClose`、`referenceDate`、`referenceSource`、调整口径。

公式：`涨跌% = (本时段价格 / 对应基准收盘价 - 1) × 100`，只对有限数且基准 > 0 计算。

- 常规列：盘中是当前 RTH 最近成交；盘后固定为刚结束 RTH 的收盘参考。常规涨跌相对该 RTH 的上一交易日常规收盘。盘前保留上一完整 RTH 的价格和该日涨跌，不能重算成 0%。
- 盘后 EXT：相对刚结束的 RTH 收盘。
- 隔夜 EXT：相对该隔夜开始前最近一个已完成 RTH 的收盘；不以 20:00 盘后最后价为默认基准。
- 盘前 EXT：相对即将开盘交易日的上一完整 RTH 收盘，不用隔夜最后价当基准。
- 例如前一 RTH 收盘 100、本日 RTH 收盘 103、盘后 104：常规 +3.00%，盘后 EXT 约 +0.97%；同一参考日之后隔夜 105 则约 +1.94%。这是合成计算测试，不是实际行情。

前 / 后市参考常规收盘的口径可参考 [TradingView 计算说明](https://www.tradingview.com/support/solutions/43000775782-how-are-the-most-popular-filters-connected-with-pre-market-and-post-market-calculated/)。隔夜采用上面明确规定的本产品口径，不承诺与每个软件默认配置逐位一致。

### 时间和缺失规则

- 用 `America/New_York` 判断交易时段，用 `Asia/Shanghai` 展示北京时间；存储 UTC 时间戳。不要固定加 12 或 13 小时。
- 普通常见窗口为纽约盘前 04:00–09:30、常规 09:30–16:00、盘后 16:00–20:00、隔夜 20:00–次日 04:00；实际必须以所选源交易日历 / 时段为准，处理周末、假期、半日市和维护间隔。
- 隔夜跨午夜不能重置基准；交易日期与纽约日历日期是两个字段。日历无法核实时显示“时段待确认”，不自动声称开市。
- 当前常规时段没有进行中的 EXT：自动模式可显示最近已结束的 EXT，但必须标明“已结束 + 日期”，且不混入“仅当前时段”的实时排行。
- 显式选盘前 / 盘后 / 隔夜可查看最近一场该时段的留存数据；历史排行与当前排行状态分开标识。初次启动且无历史快照时允许为空。
- 没有该时段成交、权限不足、源不覆盖、连接断开、数据过期分别展示原因。无 EXT 不得用普通收盘填充；不得把 null 转为 0%。
- 默认 EXT 按最近真实成交计算。只有买卖报价时，成交列保留“无成交”；可另设明确的“报价中间价观察”模式，标注价格类型，不能无提示混进成交价排行。
- 低成交频率不等于网络断线：分别记录连接健康与最近成交年龄。实时权限、最新成交距现在多久、网络是否连通是三件事。
- 休市保留最后有效值和日期；开新时段时，旧值不能带着新时段标签继续参与实时排行。
- 拆股 / 反向拆股后的杠杆 ETF 必须核对价格与基准调整口径；无法核对时返回基准未知，不制造巨大虚假涨跌。

## 7. 首选长桥适配器实施细节

1. 使用当前官方 Node.js SDK，核实包名、版本、ESM 用法及 Windows 原生二进制兼容性，再固定依赖。仅创建行情 QuoteContext，不创建交易上下文。参考 [入门文档](https://open.longbridge.com/docs/getting-started) 和 [Node SDK](https://longbridge.github.io/openapi/nodejs/classes/QuoteContext.html)。
2. 在服务端开启 `LONGBRIDGE_ENABLE_OVERNIGHT=true`。旧 LONGPORT 名称有兼容支持，但新代码统一一个配置体系。大陆访问可按官方文档配置地区 endpoint，不假定海外地址连通性最好。参考 [隔夜启用说明](https://open.longbridge.com/docs/qa/broker)。
3. 首次拉快照，再合并实时推送；处理快照与订阅的竞态：先订阅并暂存增量，再应用快照和更新的增量，或使用等价、已验证的 SDK 流程。
4. 快照有 `preMarketQuote`、`postMarketQuote`、`overnightQuote`；推送应按会话字段路由。SDK camelCase 与原始协议 snake_case 不要混用。参考 [SecurityQuote](https://longbridge.github.io/openapi/nodejs/classes/SecurityQuote.html)。
5. 推送是增量字段，不是每次完整对象；未出现的字段不能被置空，0 和未提供也要区分。按证券、时段和连接 generation 合并；乱序旧包不覆盖新包。重连的序列号作用域按源协议处理。
6. 不盲目信任 `prevClose` 永远指向你想要的日期。核实快照日切行为，在本地保存按 RTH 交易日索引的收盘参考，初次加载用同源历史日线补齐最近数个交易日；验证 09:20 前后与 16:00 后，不用 Yahoo 多日 chartPreviousClose 替代。
7. 有明确官方收盘则优先使用；只有当日最后 RTH 成交时可以标“收盘参考，待确认”，不得假称官方收盘。收到合法收盘修正后只更新对应日期基准并重算受影响字段。
8. 统一内部证券身份；例如展示 AAPL，适配器映射 AAPL.US。BRK.B / BRK-B 等特殊代码通过源静态信息核实，不能简单拼后缀覆盖所有标的。
9. 维护全局去重订阅集和引用计数，切换组不重复建连接；移出最后一个组后取消订阅。允许多浏览器标签页共享服务端上游连接。
10. 指数退避重连并加随机抖动；认证失败停止无意义重试，提示重新配置。遇到限流按源规则退避，不以每秒轮询 30 个代码替代推送。
11. 以 capability 标识实时 / 延迟 / 指示价 / 未知；无法确认无固定延迟时显示“时效待确认”。不得以 HTTP 200 或每秒刷屏证明实时。
12. 不自动切到其他供应商并掩盖切换。以后启用备用源也需明确来源、交易时段和基准来源；本期只保留接口扩展点。

## 8. 后端与浏览器的数据通路

建议：`供应商 WebSocket → Node 适配器 → 分时段报价状态 → SSE → Vue 自选表`。

- 新增 `GET /api/watchlist/quotes?symbols=...` 返回快照和每行状态，新增 `GET /api/watchlist/stream?symbols=...` 提供 SSE；保留原 `/api/watchlist` Notion 导入。
- SSE 路由必须在通用 JSON 路由之外处理。设置 text/event-stream、no-store；心跳与价格事件分离。客户端断开、服务退出时释放监听与订阅引用。
- 服务器校验代码、数量、URL 长度，禁止传入任意外部 URL。只允许本机配置的供应商端点；默认继续监听 127.0.0.1。凭据不进 public、localStorage、响应或日志。
- 报价状态保存在内存即可；当前时段所需的日历和日收盘基准可小规模缓存。新流不能套用旧 Yahoo 的 60 秒 TTL，也不能把一小时前 fallback 标成 live。
- 后端可每 100–250ms 合并一批推送，前端最多每帧更新可见状态；这只是本地处理目标，不宣称端到端市场延迟保证。
- 整个页面只维护一套规范化 quote store；大表、紧凑面板和分组视图都读取它。图表页面不可因每次自选价格变化执行全局 render。
- 降级到短轮询仅用于上游已实时订阅而浏览器 SSE 不可用的本地快照通道；状态显示“轮询更新”，不改变上游数据时效的标识。
- 启动无凭据时：现有公开数据模块正常；新自选看板显示“实时源未配置”，分组与排序设置仍可用；测试夹具只用于测试，不作为正式行情。

## 9. 排序与自动重排

支持列：代码、常规价格、常规涨跌%、EXT 价格、EXT 涨跌%、更新时间。点击表头切换升 / 降序，展示方向和 aria-sort。

- 排序按原始数值，不按格式化字符串。0 为有效值，null / NaN / Infinity 视为不可用。
- 升序、降序都把不可用值放末尾；同值采用稳定代码次序，不能每次随机跳行。
- 对“当前实时排行”，先判断当前 sessionId 和数据资格，再排序；旧时段、延迟、未知时效的记录在末尾独立显示状态，不混入实时冠军。
- 历史模式允许在同一场已结束时段中排序；不要将不同日期混为同一排名。
- 默认实时更新价格；自动重排最多每 1 秒执行一次，提供“冻结排序”。鼠标按下到松开、键盘操作菜单时暂停移动，避免误点另一只股票。
- 分组视图只改变组内次序；全部排行按唯一证券去重。组折叠不停止对该组其他必要自选的状态维护。
- 每组允许记住自己的排序选择；默认 EXT 降序。用户切换到“常规涨跌%”后不被后续推送强制切回。

## 10. 动效与图表生命周期

采用 Vue 内置 Transition / TransitionGroup 和少量 CSS，不引入重型动画库。参考 [Vue Transition](https://vuejs.org/guide/built-ins/transition.html) 和 [TransitionGroup](https://vuejs.org/guide/built-ins/transition-group.html)。

建议节奏：页面离场 100–140ms，进场 160–200ms；只对内容区做 opacity 和 4–6px 的 translateY；侧栏、顶栏、自选面板保持稳定，不跟着整页闪动。不要 animation: all，不做大范围缩放和模糊。

实现注意：

1. 每个页面有稳定的单根容器和 page key，不能只给某个模板加 transition。若用 `mode="out-in"`，离场时旧页面的数据与身份必须保持稳定，不能旧标题配新内容。
2. 当前 render() 使用 getElementById，出入场同存时容易选中旧节点或出现重复 ID。优先使用页面元素 refs、组件挂载钩子和 after-enter；旧图表在真正卸载后 dispose，新图表在容器有尺寸后初始化 / resize。
3. 不能指望 `await nextTick()` 就代表 200ms 过渡结束；用 Vue 钩子协调。快速连续点不同页面，最后选择应胜出，旧请求和旧动画不得覆盖新页面。
4. 同标的刷新保留旧内容并显示轻量更新态；跨标的加载不能把 AAPL 的数据放到 NVDA 标题下。保留现有请求序列号和 AbortController，按资源参数校验响应归属。
5. 首次加载可用固定高度骨架；普通价格推送更新对应文本，不清空整个表、不重建 ECharts。
6. 分组展开 / 收起约 160–180ms；排序位移约 180–220ms，用稳定证券 key。表格语义与 TransitionGroup 的 DOM 合法性一起验证，不能生成浏览器自动纠正的非法 tbody。
7. 价格变化仅短暂强调对应单元格，使用现有涨跌色的低透明度底色；数字直接更新，不做从旧价慢慢数到新价的动画。
8. `prefers-reduced-motion: reduce` 关闭位移 / 淡入淡出，逻辑仍正常完成；不要让清理依赖可能不触发的 CSS 事件。
9. 保留用户图表缩放、当前选择及页面滚动策略；不要为加动画统一启用每次图表全量重播。

## 11. 验收与交付

必须用有意义的计算 / 状态测试，而不是只测试几个 CSS class：

| 场景 | 预期 |
| --- | --- |
| 100 → 103 RTH → 104 盘后 | 常规 +3%，EXT 约 +0.97%，互不覆盖 |
| 隔夜跨纽约午夜、夏令时切换 | 基准不在午夜错误清零，时间正确 |
| 周一盘前 / 假期 / 半日市 | 找到上一个真实 RTH；按实际日历分类 |
| 反向拆股、缺基准、非有限数 | 不制造异常排行，显示明确原因 |
| null、0、负值、并列 | 数值排序正确，不可用值始终末尾 |
| 同股多个组 | 所属组正确，全部排行去重，上游只订阅一次 |
| 旧存储迁移 / 损坏存储 / 导入 | 原自选可恢复，不重复、不丢失 |
| 增量缺字段、乱序、重连旧快照 | 不清掉已有字段，不覆盖新报价 |
| 新时段尚无成交 | 不把上一场价格当作新时段 EXT |
| 无权限 / 断网 / 源不覆盖 / 已休市 | 状态可区分，不显示假的实时绿点 |
| 连续切页、刷新、切标的、切主题 | 不串数据、不白屏、不泄漏图表和监听 |
| Reduced motion / 键盘 / 手机 | 可操作、焦点正确，无整页横向溢出 |

执行语法检查、新增模块测试和现有工作台回归；交付前跑 `npm.cmd test`。新增 JS 文件也纳入 check。Windows 如遇既有路径权限问题，可在当前会话使用 `NODE_OPTIONS=--preserve-symlinks --preserve-symlinks-main`，不要修改系统全局环境。

真实浏览器检查浅色、深色、390px 手机、约 1024px 与 1600px 以上桌面；截图对照原 tokens，检查右面板不会挤坏热力图 / 期权图。动效需要实际快速切页和检查布局，DOM 测试通过不代表视觉验收。

数据验收分成三项报告：静态 / 单元测试通过；真实浏览器交互通过；真实盘前 / 盘后 / 隔夜数据逐项验证。交易时段未到或无凭据时，只能报告前两项，不将样本测试当成实时验证。对比 TradingView 时先核对相同交易场所、时间及价格类型，不把两个源不一致一律判为程序错误。

最终交付：完成代码、数据源配置说明、分组迁移说明、真实覆盖表、测试结果、浏览器截图、尚待验证事项。若仍需用户操作，只列出具体缺少的凭据 / 权限 / 实际验证时段，并先完成不依赖它的工作。
