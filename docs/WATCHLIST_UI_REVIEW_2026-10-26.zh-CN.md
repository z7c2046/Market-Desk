**Market Desk 自选面板：交易者视角的 UI 与交互改进建议**

评估日期：2026-10-26，北京时间。范围为自选面板的位置、信息层级、分组、按钮、行情时段和刷新体验。本次仅评估并新增这份文档，没有修改应用代码。

**1. 建议采用的方向**

保留现有分组、折叠和拖拽能力，将自选从导航下方移到独立、全高的面板。桌面布局推荐“左侧窄导航 + 中间研究区 + 右侧自选”，让当前观察时段的价格、涨跌幅、排序和分组统计保持一致。

配色继续沿用现有浅色/深色表面、蓝色选中态和红绿涨跌。优先改变空间分配和报价含义，随后再调整边框、圆角与间距。

**3. 已确认的问题及定位**

| 问题 | 当前依据 | 对使用者的影响 |
|---|---|---|
| 首屏默认常规时段，等待报价后校正 | public/app.js:531–533、2247–2260 | 当前本应盘前时，标签仍可能先显示常规 |
| 常规价固定为主行，EXT 放在次行 | public/index.html:234–273 | 北京白天最关注的信息反而最小；两种价格没有清晰主次 |
| 备用推送会将常规价填入当前时段 | src/watchlist-quotes.js:112–124 | 出现有盘前标签、却实际沿用历史常规价的情况 |
| 自动模式在当前时段无报价时回退到其他时段 | public/watchlist-model.js:215–255 | 各行可能同时代表不同场次；侧栏没有充分展示“已结”状态 |
| 分组排序与均值使用常规涨幅 | public/app.js:1863–1903 | 观察 EXT 时，组内排序、组标题和组间顺序可能依然表达常规表现 |
| 公共备用源的首次报价按每批 8 支依次等待 | src/watchlist-quotes.js:245–256 | 较慢的一批会推迟完整快照；没有测得本机全列表的实际耗时 |
| 总览上的全局刷新不显式刷新自选 | public/app.js:2517–2523 | 用户点击“刷新”，容易以为自选也已经立即刷新 |
| 成功的 SSE 消息只更新价格，不更新市场时段 | public/app.js:2291–2308 | 跨时段切换依赖后续快照触发，需独立的场次更新机制 |
| 时段函数只有星期与时钟规则 | src/market-sessions.js:62–105 | 节假日、提前收市和夜盘场地间歇不能只靠该函数准确表达 |

本地接口样本：2026-10-26 18:40 北京附近，`GET /api/watchlist/quotes?symbols=MU` 返回当前场次 `pre`，备用源为 Yahoo Finance，`isConfigured=false`；MU 常规价格 877.55、常规涨幅约 +2.4589%，源时间 `2026-10-23T20:00:01.000Z`，但 `pre.price=null`、`overnight.price=null`。随后 SSE 返回 `session=pre`，价格仍为 877.55、涨幅仍为 +2.4589%，源时间仍是 10 月 23 日的常规报价。

这证明当前本地备用数据路径存在时段错标。上述数字只是在本地服务观测到的返回值，不是对真实市场成交价的独立验证。两次单标的 HTTP 请求分别约 3.0 秒和 48 毫秒，缓存条件不同，不能据此给出页面性能结论。

另需核对盘前涨幅的收盘基准：该 MU 快照的 `pre.referenceClose=856.49`，而最后一笔已完成常规收盘报价为 877.55。应根据场次所属交易日选择已完成的常规收盘记录，不能把字段名 `prevClose` 当作始终适合当前盘前的基准。由于这次盘前价格为空，未据此计算或验证真实盘前涨幅。

**4. 布局方案**

- 左侧导航默认收窄为约 64–72 CSS px；保留图标和可访问名称，可展开查看文字。
- 右侧自选默认约 360 CSS px，可拖动至 320–440 px；这是待实际浏览器验证的起始尺寸。
- 自选拥有独立滚动区；标题、观察时段和列头固定，只有分组与股票滚动。
- 将“板块温度”放回市场总览的内容网格，避免形成两条竞争空间的右侧栏。
- 已有“快捷自选”、左侧自选和完整看板共用同一套数据投影与操作约定。桌面同时只保留一个常驻自选列表；完整看板用于展开更多列。
- 不根据图表切换重置自选滚动位置、展开组、选中股或手动顺序。
- 中等宽度以可收起侧栏呈现；小屏使用独立自选页面或抽屉。不要为了塞下三栏继续缩小价格文字。

**5. 股票行与分组**

默认列为“代码 / 当前时段价格 / 当前时段涨跌幅”。例如观察盘前时，列名直接显示“盘前价 / 盘前%”；观察隔夜时显示“隔夜价 / 隔夜%”。

主行使用代码和等宽数字，价格右对齐；建议从 13–14 px 字号、32–36 px 紧凑行高开始验证。普通行使用轻分隔线，蓝色只突出当前选中股票，不给每只股票单独做厚边框卡片。涨跌仍保留正负号，不能仅靠红绿区分。

公司全名、市值和历史常规收盘移入行详情、可聚焦提示或可选列。普通状态不需要每行重复盘前图标；时段在面板顶部统一说明。行与面板时段不同、行情延迟、无报价或暂不可用时，再在该行显示例外状态。

没有本场报价的实际呈现应类似：MU 的盘前价和涨幅为“—”，次行“暂无盘前报价 · 参考收盘 877.55（10/23）”。不能把参考收盘移到盘前主价位置，也不能以 0% 代替缺失。

保留存储、芯片、光、ETF、数据中心、万亿市值等分组及其成员关系。分组标题保留名称、数量、展开状态；增加的是口径清晰度，而非重新组织分组。

- 分组默认位置保持用户顺序，不随每次行情刷新移动。
- 组内排序遵从用户选择；点击当前时段涨跌列时，按该时段排序。
- 分组均涨幅也采用观察时段，显示有效覆盖数量，例如“盘前均涨 +0.8% · 6/8”。此处仅为文案示例。
- 缺少当前时段报价、已过期或口径不匹配的数据不进入当前有效均值；空值排在末尾。
- 小面板默认不增加市值、成交额、迷你走势图等额外列。

**6. 按钮与操作约定**

| 控件 | 建议行为 |
|---|---|
| 添加 | 主标题旁常驻一个“+”；弹窗搜索标的并选择目标分组，默认沿用最近操作组 |
| 更多 | 放入新建分组、管理分组、列设置、密度、导入导出与删除管理 |
| 收起 | 折叠整个自选面板；再次展开恢复状态 |
| 观察时段 | 显示“自动 · 当前盘前”；下拉可选自动、隔夜、盘前、常规、盘后 |
| 分组 / 排行 | 分组保留用户结构；排行对全部自选去重后按当前观察时段比较 |
| 列头排序 | 替代现有价格、EXT 价、常规%、EXT%、代码、市值等七个常驻小按钮 |
| 分组更多 | 放入重命名、组内排序、添加、移动等；悬停和键盘聚焦都能访问 |
| 刷新自选 | 背景更新报价，保留现有行、滚动位置和选中状态；与刷新整个工作区区分 |

“观察时段”只改变查看的行情维度，不代表实际市场切换了时段。手动固定盘前时，应写“查看：盘前（已结束）”，同时保留小号“市场：常规交易”，避免两者混淆。手动选择跨刷新保持，用户主动切回自动后再跟随市场。

普通点击股票在中间研究区打开对应详情或图表；列表保持选中和原位。上下键切换、Enter 打开、Escape 关闭菜单可作为键盘约定。拖动仅从明确手柄发起，排序菜单提供非拖动替代方式。

常用按钮建议采用约 28–32 px 命中区域；触摸布局加大。股票代码不要因市值标签被挤成省略号；非关键长公司名可以省略，但需提供可聚焦的完整名称。

**7. 北京时间与自动时段**

面板用北京时间作为主显示，美东时间作为辅助。以用户截图场景为例，顶部可显示“自动 · 当前盘前”，第二行“北京 18:35 · 纽约 06:35 EDT · 常规开盘 21:30”。这个例子对应截图的 10 月 26 日，不应硬编码到界面。

以下为现有常见交易安排的展示参考；夜盘行具体采用长桥公开说明，不代表所有提供商和场地相同。

| 场次 | 美国夏令时期间的北京时间 | 美国标准时期间的北京时间 |
|---|---|---|
| 隔夜（长桥示例） | 08:00–15:50 | 09:00–16:50 |
| 盘前 | 16:00–21:30 | 17:00–22:30 |
| 常规 | 21:30–次日 04:00 | 22:30–次日 05:00 |
| 盘后 | 04:00–08:00 | 05:00–09:00 |

长桥夜盘存在至盘前开始前的间歇，夜盘还归属于下一个交易日。因此不要把 20:00–04:00 写成所有夜盘源统一且无间断的时段。以提供商/场地日历与支持的标的为准，处理美国节假日和提前收市。[长桥夜盘与时间表](https://longbridge.com/hk/zh-CN/support/topics/marketdataandtrading/Overnight20230922)、[Nasdaq 交易日历](https://www.nasdaq.com/market-activity/stock-market-holiday-schedule?display=b2b)。

自动模式必须分别处理：市场当前处于什么场次、用户在看什么场次、该股票当前场次是否有可用报价。进入隔夜时段不等于每只股票都有隔夜数据；“未接入/不支持”和“已接入但暂无报价”也不应合并为“无成交”。

当前快照显示本地使用 Yahoo 备用源；这不能证明其覆盖所有盘前或隔夜标的。夜盘支持应由实际接入与逐标的覆盖验证决定，不能通过改标签实现。

涨跌口径建议：常规相对前一交易日常规收盘；盘后相对刚结束的常规收盘；隔夜和盘前相对其场次开始前最近一个已完成常规收盘。以交易日识别收盘基准，跨北京时间零点不重置。

**8. 刷新与流畅度规则**

1. 先恢复分组、滚动位置、观察模式、选中股和手动排序。使用场地日历与校准时钟确定场次；日历无法确认时显示“确认交易时段”，不要先默认常规。
2. 同场次、同交易日、来源明确的旧快照可立即显示，并标注“更新中”。跨场次缓存只能作为带日期的参考；无可用缓存时在固定高度行内显示占位。
3. 自选报价独立于新闻、热力图和加密市场加载。优先返回已缓存快照，再分批补齐；不要等最慢标的完成后才让整个列表可用。
4. 同一股票/场次请求合并，避免快照与推送互相覆盖；按场次、源时间与版本拒绝过期返回。不得用请求到达时间掩盖旧成交时间。
5. 报价只更新对应单元格，可短暂弱高亮；不闪烁整行，不重建整个列表，不反复改行高。
6. 排行视图的价格可持续更新，位置建议按约 3–5 秒节奏更新；指针在列表内或键盘聚焦、拖拽、菜单操作期间暂停重排。分组视图默认不自动调整分组位置。
7. 接近场次边界时由时钟/日历更新观察状态，服务端推送校准；新场次报价尚未到达就保留占位，不把上一场行情改名。
8. 网络失败保留带原始时间的可用数据并显示“连接中断/更新失败”；重试不重置分组或滚动位置。连接正常、行情延迟、报价过期是三种不同状态。
9. 全局刷新应定义是否包含自选。若继续保留全局“刷新”，建议包含当前可见自选，并明确每个模块的更新状态。

**9. 实施顺序与验收**

第一阶段先修报价含义与启动流程：去掉跨时段假填充，修正首屏默认场次、盘前参考收盘、场次日历、HTTP/SSE 合并和全局刷新范围。即使布局未改，先让“盘前”一词可信。

第二阶段调整面板：独立全高自选、固定工具区、当前场次单主行、保留原分组、精简按钮、统一分组统计与排序。

第三阶段补流畅度：快照恢复、优先级加载、局部更新和稳定排行。具体刷新频率应结合真实行情频率和浏览器性能测试调整。

| 验收情境 | 通过标准 |
|---|---|
| 北京下午打开页面 | 第一帧显示正确场次或确认中；没有“常规 → 盘前”的默认值闪跳 |
| 盘前没有报价 | 显示缺失状态；历史收盘仅在参考位置出现，绝不进入盘前排序 |
| MU 这次观测到的备用源路径 | SSE 不再发送 session=pre 加历史 regular 价格的组合 |
| 隔夜切盘前、盘前切常规 | 标签、列名、价格、基准和排序一致切换；第一笔报价未到时不冒用上一场 |
| 快照晚于推送到达 | 旧快照不能覆盖较新的同场次报价 |
| 扫读、聚焦或拖拽时收到报价 | 价格可更新，但鼠标/焦点下的行不突然移动 |
| 刷新或切换中间页面 | 分组折叠、滚动位置、选中股、手动排序保持 |
| 组内仅 6/8 有有效当前场次报价 | 显示覆盖数量；缺失标的不当作 0% 参与均值 |
| 周末、节假日、提前收盘、夏冬令时变化 | 依市场日历呈现；不套普通工作日时钟规则 |
| 小窗口与键盘使用 | 价格可读、控件可聚焦，常驻面板不挤压到无法阅读 |

TradingView 可借鉴的是独立观察列表、列头排序、分组和可配置列，以及同一标的的多时段信息；具体自动主价规则仍应按你的北京白天使用场景设计。[TradingView 自选说明](https://www.tradingview.com/support/solutions/43000745825-mastering-the-tradingview-watchlists/)、[TradingView 隔夜与 24 小时行情说明](https://www.tradingview.com/support/solutions/43000790593-how-to-view-the-24-hour-market-and-overnight-trading-sessions/)。

建议下一步先实施第一阶段，再按独立自选面板方案完成 UI 调整，并用真实盘前与隔夜场次验收。
