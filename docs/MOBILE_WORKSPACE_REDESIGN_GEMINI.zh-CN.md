## 1. 交付定位与核心目标

沿用本轮对话前一项的交付方式：这是一份交给 Gemini 修改代码的具体方案。本次没有修改应用运行代码。

用户目标是重新安排手机页面，使操作顺畅、容易阅读、观看顺序正确。方案不是把桌面布局缩小：手机端围绕“现在市场如何 → 我的股票如何 → 打开一只股票 → 看懂价格与图表 → 返回原位置 → 阅读相关资讯”组织。

核心验收条件：

1. 常用入口无需打开综合抽屉寻找。
2. 自选第一屏不用横向拖表格就能同时看清标的、对应时段价格和涨跌。
3. 每个价格有明确时段/数据状态；历史图表、常规收盘价和盘前报价不会混成一个“最新价”。
4. 查看详情再返回，不丢当前分组、排序、滚动位置和图表视区。
5. 页面阅读、列表横向选择与图表手势互不争抢。
6. 字体和点击区域足够大，长名字、系统大字、键盘和浏览器地址栏变化都可用。
7. 四种配色组合都适用，桌面现有工作台和用户数据得到保留。

本次证据是当前 HTML/CSS/JS 和测试入口。浏览器访问返回 `The browser access host is unavailable`，原生 UI 通道也不可用，因此**没有手机截图、真实触摸录像或帧率测量，不称为已完成实机视觉审查**。以下明确区分“源码已确认”与“实施设计/待实机验证”。

## 3. 新手机信息架构：五个稳定入口

底部固定为：**市场 / 自选 / 个股 / 资讯 / 更多**。

| 入口 | 对应既有页面 | 用户问题 | 页面记忆 |
|---|---|---|---|
| 市场 | `overview` | 市场现在处于什么状态？ | 滚动位置、热图范围/时段/板块 |
| 自选 | `watchlist` | 我关注的股票现在怎样？ | 当前分组、时段、排序、阅读位置 |
| 个股 | `chart` | 这一只股票的价格和走势如何？ | symbol、range、指标开关、历史视区 |

进入个股时，左上角优先显示“返回自选”或“返回市场”等真实来源；通过底部直接进入个股时显示“个股”，不制造不存在的返回历史。现有默认启动页偏好保留，不能强制全部用户首次跳市场。

点击已选中的底部项不复位、不重新请求、不滚回顶部。切换页和选择股票不是同一函数里隐含的副作用；分别有明确入口。

## 4. 布局壳：顶部少做事，底部负责切页，中间连续阅读

### 4.1 尺寸与层级

| 部分 | 规格 | 行为 |
|---|---|---|
| 手机页边距 | ≤359px 为 12px，其余 16px | 不随页面切换忽宽忽窄 |
| 主内容节奏 | 小组内 8px，模块内 12–16px，模块间 20–24px | 沿用现有圆角/配色，不另建视觉体系 |
| 顶栏 | 内容高 56px，加顶部 safe-area | 左：页面标题或返回；右：搜索＋当前页动作（至多两项） |
| 底栏 | 内容高 64px，加底部 safe-area | 五个等宽目标；标签 12px，常驻 |
| 底部内容留白 | 80px＋safe-area | 最后一条内容与按钮可滚到栏上方 |
| Sticky 工具行 | 常用页最多一行，通常 44–48px | 顶栏以下；不是每个筛选区都吸顶 |
| 主滚动容器 | 手机/紧凑布局使用 document 单一纵向滚动 | 弹层自己的滚动例外 |

顶部不再同时展示品牌 Logo、Market Desk、PRO、页面名、价格和三四个动作。页面标题回答“我在哪”，报价在正文摘要回答“现在是多少”，不要在 56px 一行里抢位置。

### 4.2 响应式边界

建议统一为：

- `<768px`：手机布局，纵向列表/单列内容为主。
- `768–1023px`：紧凑布局，仍用底部导航，关闭右侧自选栏；正文最大宽度 760px，允许指数/统计两列。
- `≥1024px`：保留桌面导航和多栏工作台，按既有大屏规则控制右栏。

这样普通手机横屏不会突然落入当前 768px 即开启的三栏桌面壳。引入 `isCompactLayout = matchMedia('(max-width: 1023px)')`，小手机特定排版可用 `isPhoneLayout`。不要无条件把所有旧 `isMobile` 替换为新布尔值：逐项审计导航、inert、图表交互、滚动锁、侧栏和弹层等调用方。

Shell 专属的 `min-width:768px` 规则迁到 1024；已有模块排版断点按内容需要保留。媒体查询与 JS 使用同一边界，不允许 768px 同时出现桌面侧栏和手机底栏。

### 4.3 文字和点击规格

- 主要报价 24–28px，列表价格 17–18px；价格不滚动计数、不做跳动缩放。
- 股票代码 15–16px；正文/新闻摘要 15–16px，行高 1.5–1.6。
- 公司名、来源、时间、状态 12–13px；底栏标签 12px。不能通过 9px 小字塞完桌面信息。
- 关键信息的弱化优先用 `--text-secondary`；Terminal原主题中更暗的 `--text-muted` 不直接用于手机的小字号源时间/状态。保留主题原色表，通过正确角色映射改善可读性。
- 表格数值使用 `tabular-nums`；上涨、下跌符号和状态文字保留，不只靠颜色。
- 主要点击目标至少 44×44 CSS px；输入框至少 44px 高，字体 16px；相邻小目标保证间距。
- 公司长名可截断一行，但代码、价格、涨跌幅、当前时段和错误信息不能靠省略号隐藏。
- 普通文本允许系统放大，移除 viewport 的缩放禁用。320px 宽及放大文字时允许工具栏自然增高，不能固定高度裁切。

44px 是本项目的舒适操作目标，不要误写成 WCAG 2.2 AA 的绝对门槛；该条目的最低目标为 24px 并带例外。参考：[W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。重排以 320 CSS px 为重要检查条件，必要二维图表/表格可有局部滚动例外。参考：[W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

## 5. 市场页：先交代时段，再看指数，再深入热图

### 5.1 从上到下的阅读顺序

| 顺序 | 内容 | 默认展开情况 |
|---|---|---|
| 1 | 市场状态：美股盘前/常规/盘后/隔夜/休市；北京时间；数据状态 | 一行或自然两行，始终可见 |
| 2 | 四个核心指数摘要，2×2 | 指数名、数值、涨跌；来源时间不藏到 tooltip |
| 3 | 板块热图 | 一个范围选择、一个时段/筛选入口；图表高 280–340px |
| 4 | 板块表现短列表 | 默认 5 项，“全部板块”展开；不要 3 列 9.5px 字 |
| 5 | 风险情绪、宏观摘要 | 现有指标保留，详细解释进入详情 |
| 6 | 财经新闻摘要和事件入口 | 3 条即可，引导到资讯页 |

四个核心指数直接来自现有指数数据，不发明数据。其他指数、原油、美元、美债等放“更多市场指标”，保持完整可达。Treasury 首页仍展示 10Y，详情可看 10Y/20Y/30Y。

一个视觉模块最多一行主操作。热图全部行业、来源、大小、时段等放同一个筛选面板；已生效条件以简短摘要显示，不能隐藏当前口径。

热图本体不重写成图片或新的图表引擎；默认阅读时页面能从图表区域纵向滚过。复杂缩放/钻取进入“展开热图”；既有布局、色阶和标签算法保持，并在展开模式逐项验收。

不宣称“首屏必须装下全部信息”。在 390×844 的默认字号下，目标是能读到时段、指数和热图标题/上部；实际高度以中文长文案和安全区验收为准。

## 6. 自选页：纵向报价列表作为默认，完整表格作为次级

### 6.1 顶部只留下当天要用的控制

标题行：自选＋当前分组名称；右侧“添加”。

工具行：分组选择、报价时段、排序。使用一个分组选择按钮展示当前分组，点击弹出所有分组及数量；不要把十多个分组塞成一条隐藏滚动条的胶囊带。默认先保留用户当前 viewMode/分组状态：分组模式显示组头与折叠列表，全部模式去重。

“管理分组、备份/恢复、冻结/自动重排、完整表格”放自选页面的更多操作面板。不是删除功能，也不是放进全局偏好里让用户找不到。

### 6.2 一条股票的排版合同

每条正常报价行约 76–88px；文本放大或状态异常时自然增高。使用三列：**身份 / 当前报价 / 当前涨跌**。

| 位置 | 第一行 | 第二行/状态行 |
|---|---|---|
| 左列，可伸缩 | 代码，15–16px，600 | 公司名，12–13px |
| 中列，右对齐 | 所选时段价格，17–18px | 明确的时段标签；需要时显示“常规收盘 …”作为次要值 |
| 右列，右对齐 | 同一时段涨跌%，15–16px | 源时间，12px；延迟/旧快照有文字标签 |

390px 视口建议内部宽 358px，列间距 8px，价格列约 104–116px、涨幅列约 84px，身份列吃剩余空间。320px 或大字场景允许次要状态移到整行第三行，不强行压缩代码/价格。高价标的价格允许自然增高/调整列宽，不截去有效位数冒充完整报价。

点击主行进入该股票，行为与现有 `selectSymbol()` 的选股功能一致；操作按钮与主行分开，不把“删除”和“打开图表”放到同一点击热区。优先使用可访问的真实链接/按钮，不靠不可聚焦的 `<div @click>`。

不新增默认滑动删除、长按管理或拖拽排序；这些会与页面滚动冲突。进入显式“管理”模式再提供批量/单项操作。已有删除/撤销逻辑复用，不另写一套存储。

### 6.3 报价显示模型必须一致

直接复用 `groupedRows` / `allRankedRows` 的排序和身份信息，新增纯展示投影 `toMobileQuoteView(row, context)`，不要另外请求报价或复制 WatchlistManager。

建议返回：

```ts
type MobileQuoteView = {
  symbol: string;
  name: string;
  requestedSession: 'regular' | 'pre' | 'post' | 'overnight';
  displayedSession: string | null;
  price: number | null;
  changePercent: number | null;
  sourceTime: string | null;
  receivedAt: string | null;
  status: 'available' | 'delayed' | 'stale' | 'missing' | 'unsupported';
  referenceRegular: { price: number | null; changePercent: number | null };
};
```

三条硬规则：

1. `price/changePercent/session/sourceTime` 必须来自同一个已识别的时段报价对象；不能把 `activePrice` 与另一路 `extChange` 配在一起。
2. 请求盘前、但盘前报价缺失时，主位显示“盘前暂无报价 / —”；常规收盘另列次要参考。不能把常规价上提却保留盘前标签。
3. 自动模式也要展示实际显示的时段，报价状态未知就写未知/未提供。市场正在交易不等于每只股票都有实时数据。

目前 `buildRow()`、`getSelectedExtQuote()`、`activeChartExtQuote` 有兼容回退路径；仅依赖 `activePrice` 并不足以证明元数据完整。展示层应读取对应原对象核对，后端口径不在这轮擅改。

### 6.4 排序稳定与阅读保护

保留用户原 sortField/sortDirection/freezeResort 偏好。手机端新增的是**暂时的阅读保护**，不要偷偷改写全局冻结偏好：

- 手指按住、滚动列表、焦点在某行/操作按钮、菜单打开时，价格可更新但行顺序保持。
- 用户显式选排序时立即应用一次。
- 有后台新排序时，保留旧行序并显示轻量“排序有更新”按钮；用户点后应用。第一版优先显式更新，不在手指离开 600ms 后突然自动换位。
- 新增/删除等用户操作更新对应行，保持当前可见锚点，避免全列表跳回第一项。
- 暂时顺序快照存内存，退出页时释放或与路由状态一起保留；不写成永久冻结设置。

完整八列表格仍可从“完整表格”进入，并明确局部横向滚动；默认手机列表不再靠横向滚动阅读核心报价。

## 7. 个股页：身份、当前报价、图表、细节的单一顺序

| 顺序 | 默认可见内容 | 交互 |
|---|---|---|
| 1 | 顶栏“返回自选/市场”＋代码；右侧搜索/切换标的 | 标题本身不复位 |
| 2 | 公司名、主报价、涨跌、时段/延迟/源时间 | 比顶栏报价更完整；不重复两套冲突摘要 |
| 3 | 期间选择 | 1日、1月、3月、1年、更多；当前非快捷区间要显示真实标签 |
| 4 | 阅读模式 K 线，高度约 300–360px | 页面可以纵向滑过；明确“展开图表” |
| 5 | 精简 OHLC / 成交量读数与图表口径 | 固定占位高度；详细数值可展开 |
| 6 | “指标”“复位”“加入/已在自选” | 三个明确动作，目标≥44px |
| 7 | 详细行情、相关资讯/期权入口 | 次级展开，保持来源说明 |

`RANGE_OPTIONS` 的 `1d` 当前使用日内 K 线，不是逐笔分时；手机标签建议“1日”，说明保留实际 5 分钟等数据粒度，不能因为叫“分时”就制造新的数据能力。

报价摘要允许显示当前盘前/盘后/隔夜价，但图表若只有常规时段数据，必须在图表附近写明“图表：常规交易时段”。摘要数值变化不等于图表时段变化。不要用价格摘要去猜测 K 线的最后一根数据。

“更多期间”包含全部既有范围；如果当前选择 6月/2年，快捷区必须有可见选中项或当前期间按钮，不能五个按钮全部不选中。

### 7.1 阅读模式与展开图表模式

为避免把已成熟的桌面手势变成新的复杂冲突，第一版采用清晰的两种手机状态：

**阅读模式（默认）：**

- 触摸纵向滑动用于滚动页面。
- 不在 pointerdown 上接管 touch 指针，不 capture/preventDefault，不用透明覆盖层拦截阅读。
- 保留真实图表、当前范围和价格，提供“展开图表”显式按钮；不是用截图替代。
- 对图表 DOM 的允许手势至少保留纵向滚动与页面 pinch-zoom；还需检查内部 canvas 的 touch-action，不能只改父容器后宣称解决。

**展开图表模式：**

- 在视口内提供独立图表操作空间，隐藏页面底栏，顶部有 44px 返回按钮和代码/期间。
- 保留现有单指拖动、时间轴/价格轴缩放、复位和“回到最新”等能力。
- 现有引擎只管理一个 active pointer，不承诺已有双指缩放。第一版提供可点击的“放大/缩小/最新/复位”控制，复用已有几何算法；若新增 pinch，单列任务与测试，不能覆盖旧算法。
- 离开时保留刚才图表视区，返回页面原 scrollY，不跳顶部。
- 不强制旋转、不依赖 iOS 一定支持的 Fullscreen API；浏览器横竖屏均可操作。

`touch-action` 在手势开始时决定浏览器处理方式，因此必须先点击进入展开模式，再开始操作，不能在同一手势中临时切成 `none`。参考：[MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)。

### 7.2 引擎的最小改动合同

`bindKlineGestures()` 增加可查询的交互策略，例如 `options.getInputPolicy()` 或可更新 setter；默认策略保持当前桌面行为。触摸阅读模式下，onPointerDown/onPointerMove/轴操作都需要走一致的跳过路径，不只是跳过一个 preventDefault。

进入/退出展开时先结束 active pointer、flush/取消待处理 frame、释放 capture，再切策略；不能留下拖拽状态。改变布局只 resize，不 fitContent/reset，也不重新 setData。

建议把已有 chart-panel 子树用 Vue Teleport 移到统一 overlay root，`:disabled="!expanded"`；**移动同一个 DOM 节点**，不创建第二个 `id="price-chart"`，不以 v-if 交替销毁两套图表。验证 `_hostEl`、图表实例和 gesture controller 身份保持。移动后通过既有 ResizeObserver/尺寸更新处理。

全屏时 workspace 可设 inert，因为图表已移到其外部；若使用同一父树的 position:fixed 方案，则不能把包含图表的祖先设 inert。不得留下祖先 transform/overflow 导致弹层被裁切的问题。

不变项：KLINE_SCHEMES、MA/DEMA 色、现有几何公式、桌面滚轮/拖动/轴交互、显示指标、图表数据源。新增手机策略必须用测试证明桌面默认策略原样。

## 8. 资讯、财报与宏观页

### 8.1 资讯首页

顶部二级分段：**快讯 / 财报 / 宏观**。手机一行三个等宽按钮，目标高44px。不要把“AI”“来源”“宏观热点”“搜索提供商”等都放成并列主导航。

快讯默认单列，顺序为：当前筛选摘要 → 新闻列表。新闻卡按“标题 → 来源与时间 → 简短摘要 → 操作”阅读；标题16px，最多约3行，摘要15px。图片可保留，缺图不留占位大洞。来源名、发布时间不能只在 tooltip 中出现。

搜索与筛选是明确入口：

- 页内“搜索新闻”只搜索新闻，不跳股票图表。
- 来源/股票/分类等筛选集中到一张筛选 sheet，已生效条件回显并可清除。
- AI 搜索是一个明确动作；查询结果、失败、部分成功、空结果按当前业务区分。提供商配置收进“搜索选项”。
- Tree 快讯和普通新闻继续使用已有独立数据逻辑。可用一个清楚的源类型切换，但不能把多个提供商命中当作多个独立证据。

阅读中收到新条目时不在顶部自动插入并把正文推走。显示“有 N 条新消息”按钮，用户点击才合并并滚到新的起点；当前位置在最上方且未操作时是否自动更新可后续测试，首版用明确动作。后端抓取与缓存不因展示缓冲改动。

桌面继续等宽不同高度瀑布流；手机成为单列是响应式重排，不需要删除原桌面 masonry。

### 8.2 财报：先选日期，再读当天

现有小手机会把整周列按天堆叠，数据多时需要滚过大量公司。改为：

1. 本周/下周选择（保留 `EARNINGS_WEEKS` 与 `activeEarningsWeek`）。
2. 日期条，五个交易日，各有日期、星期、条目数；每项触达≥44px。
3. 当前筛选摘要＋筛选按钮。
4. 当前日期的盘前/盘后/时间待定三组公司列表。

首次进入若今天位于所选周且有定义，选今天；否则选该周第一交易日，并显示真实日期，不把它叫“今天”。切周优先保留同星期位置，目标周无该日则回退第一日。切筛选不自动跳到另一天；当天无结果显示空态和“清除筛选”。

分组选项、AI 链、时段、代码搜索收在筛选 sheet；筛选即时作用或点击“应用”二选一，本方案选择有草稿的“应用/重置/取消”，取消不改当前列表。

可提供“整周日程”次级视图，按天纵向显示；不横向拖五个200px的列。时间严格使用数据已有字段和时区，不从 BMO/AMC 标签推造具体分钟。

### 8.3 宏观

按日期的纵向事件列表，顺序：时间（含时区）→事件→重要性→已公布/预期/前值。屏宽不足时数字变成第二行三格，不把事件名挤成几字。缺值显示“—”，不当作0。

“宏观日历”和地缘专题分开到可折叠区域，避免进入资讯后先穿过一大段专题才能看到今天的事件。真实来源与更新时间保持可见。

## 9. 更多里的 Crypto、资金与期权

### Crypto

首屏：所选币种/报价摘要 → 币种选择 → 期间 → 图表 → 币种列表。列表采用代码/价格/涨跌三列，24/7 语义保留，不套美股盘前/盘后标签。图表按同样的阅读/展开规则处理，但使用 ECharts 适配，不把 Lightweight Charts 控制器直接套过去。

### 资金

顶部只选“板块轮动 / ETF 净申赎”，随后数据日期和来源说明。散点/柱图在其下；列表作为手机辅助阅读，按当前真实数据生成。CSV 导入放操作面板，保留其“用户提供净申赎”的业务口径，不能用成交额冒充净流入。

### 期权

先选标的＋到期日，再显示现价与关键持仓值，之后是 OI/GEX 和范围筛选，再读持仓分布。

当前主要可见实现是 `.butterfly-row` 的 DOM 蝶形条；`#options-chart` 在 HTML 里是 `display:none` 的兼容容器。**手机适配优先改可见蝶形条，不能只改隐藏 ECharts 后宣称完成。**

蝶形条内部两侧对称，行权价列固定且可读；数值长时放到各自柱条下一行，不能盖住 ATM/现价标记。默认保留用户当前范围；若采用居中现价的显示窗口，仅影响视口，不改变已有墙值计算和源数据。

保留“集中持仓不保证支撑/阻力”和数据延迟说明，但用12px可读文字；折叠更长方法论，不能把关键状态都收起。

## 10. 搜索、Sheet、设置与键盘

### 10.1 股票搜索独立成任务

点击全局搜索进入专用搜索层：顶栏“搜索股票”＋取消；下面是输入框、最近查看、自选匹配、直接打开代码的动作。

现有 search() 只校验代码再选股，因此首版不要承诺全市场公司名称搜索。可以对现有自选/本地名称表做本地名称匹配；未接证券搜索 API 时，提示“输入代码，或搜索已保存的名称”。外部直接输入代码仍走当前合法性校验和图表加载。

最近查看最多10项可选持久化为独立 `market-desk-recent-symbols`，只存代码和顺序；不能把未经验证的 API 数据全塞进 localStorage。取消搜索恢复原页面与滚动位置，不触发选股。

输入时先显示本地结果，网络加载不阻挡输入。无效代码错误就地显示，保留输入。点击结果只关闭搜索并导航一次；已经在当前 symbol 时，不隐式 resetPriceChartZoom。

iOS 自动键盘聚焦必须在真实点击链路内处理，不能先等待网络再 focus。实际设备上若浏览器不允许自动打开键盘，输入框仍在可视区且一次点按可输入，不能循环抢焦点。

### 10.2 统一浮层行为

短选项（分组、时段、排序、更多）用底部 sheet；长内容（搜索、设置、新闻详情、展开图表）用完整可用视口的面板。不要所有东西都硬塞进78dvh抽屉。

统一 header、44px关闭按钮、scrollable body、必要时固定 action footer。顶部细横线仅作视觉提示，不再是唯一小尺寸关闭按钮。可拖动关闭不是首版必要项，避免与内容滚动争夺。

采用单个手机 overlay 入口，状态为 `null | search | more | group | session | sort | filters | preferences | chart`。既有详情/新增/备份弹窗通过适配接入；一次只让一个主浮层活跃。父面板进入子设置时替换内容并保留返回路径，不叠两个 scrim。

所有弹层尽量挂在 `#overlay-root`，该节点是 workspace 的兄弟。背景设 inert、禁止背景滚动；焦点限制只收集可见、可交互元素。关闭回到真正的触发按钮，不能统一回到已移除的 `.settings-trigger`。

点击遮罩只关闭允许取消的短面板；有未应用草稿时按已定义取消规则处理。错误信息使用 aria-live；普通价格流不逐笔朗读。

### 10.3 键盘和安全区

优先用正常文档流、`min-height:100svh` 和弹层 `100dvh`，而不是给整个页面锁死 `100vh`。有键盘时 sheet body 可滚，当前输入与提交/取消均可到达。

必要时使用 `visualViewport.height/offsetTop` 限制浮层实际可见高度；注册 resize/scroll 时合并到每帧一次，卸载清理。不能只看 height 下降就判断键盘：还要有可编辑元素 focus，并排除旋转/浏览器缩放，阈值需实机校准。

编辑时可隐藏底部导航；收起键盘后还原，不让页面整体高度反复跳动。不新增页面级 `touchmove.preventDefault()`。背景滚动锁保留原 scrollY 与原 inline style，关闭时准确恢复；横竖屏切换和多个弹层退出也必须清理。

屏幕键盘可能改变 visual viewport 而不改变 layout viewport，这是需要补测的边界。参考：[MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)。

## 11. 返回、滚动和用户状态：必须先设计，再改样式

### 11.1 单一导航所有者

用一个手机导航适配层统一写 history；保留既有 hash 路由和桌面入口兼容，不安装新 Router。

建议 history.state：

```ts
type WorkspaceHistoryState = {
  owner: 'market-desk';
  version: 1;
  entryKey: string;
  page: string;
  symbol: string;
  chartRange: string;
  newsSubView: string;
  parentEntryKey?: string;
  overlay?: string;
};
```

URL 至少仍支持原来的 `#overview` 等入口。首次启动 replace 当前条目；切换不同主页或打开详情 push 一次；点当前主页不 push。onPopState 只恢复，不再 push。去掉 page watcher 中会清空数据的 `replaceState(null,...)`，路由监听只管数据/渲染。

捕获来源状态必须在改变 symbol/page 前完成。现在 selectSymbol 先改 symbol 再 navigate，手机新适配层不能照搬这一顺序保存快照，否则“返回自选”的源记录已经变成详情标的。

### 11.2 返回规则

| 当前状态 | 返回动作 | 恢复内容 |
|---|---|---|
| 普通 sheet / 搜索 / 设置 | 先关最上层 | 原页面、触发点、scrollY |
| 展开图表 | 退出展开 | 原图表实例/视区＋原页位置 |
| 从自选打开个股 | 返回自选 | 原分组、时段、排序、原股票所在行 |
| 从市场打开个股 | 返回市场 | 原热图/板块状态、scrollY |
| 从外部直接打开个股 | 安全返回默认主页或自选 | 不假设 history 一定属于本应用 |
| Android 系统返回 / 浏览器后退 | 与可见返回按钮一致 | 不先退出页面再留一个弹层 |

如果使用 history 管理弹层，打开只 push 一个 overlay marker，关闭按钮只有在当前条目确属本应用弹层时才 history.back；popstate 关闭不再次 back。浏览器 forward 也要正确恢复或规范化 marker，不能出现幽灵遮罩。普通页面选择一旦发生，应消费/替换弹层 marker，避免返回时先弹出无意义旧菜单。

### 11.3 阅读状态存储

内存保存 `Map<entryKey, ViewState>`，至少包括 scrollY、可见行 symbol/偏移、分组、排序、时段、新闻筛选/锚点、选中财报日和图表视区。已有持久化用户偏好继续用原键；不要把所有临时滚动每帧写 localStorage。

恢复优先用稳定业务 ID＋相对顶栏偏移定位，再回退 scrollY。金融列表价格更新后行高可能变化，单靠绝对scrollY不足。图像明确宽高/aspect-ratio，减少晚到图片把锚点推走。

恢复发生在目标 DOM 和数据满足条件以后，等待必要的 nextTick/ResizeObserver/渲染就绪信号；不能用固定 setTimeout(300) 猜。恢复页面位置使用瞬时滚动，不播放一次长“回程动画”。

当前离开 chart 会 `disposePriceChart()`。如果保持这个生命周期，就必须在销毁前记录可见时间范围、价格轴手动范围、autoScale/followLatest，并在同 symbol+range 再次创建后恢复；不以“变量 symbol 没丢”作为图表视区没丢的证明。切新 symbol/range 才按当前策略初始化。

## 12. 丝滑感的工程要求与可测指标

不要把“丝滑”写成保证 120fps，或只把300ms动画改成150ms。先完成操作链路，再记录实际性能。

### 12.1 去除与数据无关的等待感

`triggerPageLoadingPulse()` 当前为导航强制维持加载提示。删除手机路径里仅用于装饰的500–700ms pulse；导航按钮选中态和标题应立即更新。仅真实请求未完成时显示相应模块加载状态。

这是加载反馈语义的修正，不是声称现有 pulse 阻塞 JavaScript 500ms。缓存存在时继续显示缓存，并标明更新时间；首次无内容才使用匹配最终结构的 skeleton。

旧测试若要求“点击导航必出现固定加载 pulse”，应改为“导航即时响应、真实请求控制loading、缓存内容保持可读”，而不是为了通过旧断言保留假等待。

### 12.2 动画策略

- 手机主页面切换不做纵向位移，不让旧页和新页并排/上下共同撑高滚动容器。可直接切换，或只给非布局关键内容100–140ms淡入。
- Sheet 开合180–220ms，以transform/opacity为主；不动画布局高度、blur或大型阴影。
- 减少动态效果时直接进入最终状态；保持相同事件与焦点处理。
- 不给所有按钮永久 `will-change:transform`，不在持续价格更新时触发布局动画。
- 触屏不继承桌面hover上浮；仅在 `@media (hover:hover) and (pointer:fine)` 中应用桌面悬停效果。
- 不要用transform给整页过渡后又把固定浮层放在其内部，形成新的固定定位包含块。

### 12.3 数据与渲染

复用现有请求序列/取消机制；快速切股票后旧响应不能覆盖新页标题或报价。可见页根据现有缓存策略刷新，不为每次开sheet重载行情。

价格更新只改变必要内容；在一帧内合并多个到达的UI更新。不要把“限制绘制频率”混成“丢弃行情数据”：存储更新与可视绘制可分开，源时间继续准确。

一个容器只保留一个有效 ResizeObserver 和一个 chart instance。进入页面、after-enter、watcher、resize 可能触发同一次绘制，应建立可取消的每帧调度，检查实际调用次数；不要直接移除所有 render 后漏绘。

### 12.4 本项目验收目标

| 场景 | 目标 | 证明方式 |
|---|---|---|
| 点底部导航/开筛选 | 不等待网络；测试设备点击后约100ms内可见反馈 | 同设备重复测量，不凭主观描述 |
| 普通列表滚动 | 60Hz设备以接近帧预算的稳定滚动为目标，无重复明显卡顿 | 帧时间、Long Task、屏幕录像 |
| 返回自选 | 原可见股票/分组恢复，无跳顶部 | 前后行ID/偏移和视频 |
| 价格更新 | 价格变、行序和版面稳定 | 持续推送fixture，记录锚点变化 |
| 加载/图片到达 | 不把正在阅读的标题/操作推走 | 录制layout shift，并标记用户触发的预期变化 |
| 图表展开/关闭 | 同一个图表，状态保持 | 实例identity、时间/价格范围、截图 |

“100ms”“60Hz”是本项目验证目标，不是本次已经测得的结果。实验室结果与真实手机/线上用户指标分开汇报，不能用开发电脑通过替代iPhone/Android体验。

### 与配色工作的合并顺序

1. 先建立配色契约与基础状态，再进行手机DOM重排，最后扫手机组件颜色。
2. CSS加载建议：`styles.css → mobile-layout.css → color-palettes.css`；配色文件只控制颜色/阴影，手机布局文件只控制结构、尺寸和触摸行为。
3. 新组件消费已有 `surface-* / text-* / semantic-* / selection-*`，不要另写一份移动端主题。
4. 四种组合是 Terminal Light/Dark、Cobalt Light/Dark；检查手机按钮底/字角色，不能把暗色浅蓝文字token当实底按钮背景再配白字。
5. 颜色和布局不能各自新增重复的pref watcher、浏览器meta管理或偏好存储。

## 14. 旧代码的迁移方式

不要在13,000行样式末尾增加500行 `!important` 当作完成。按以下步骤逐块迁移：

1. 记录现有手机规则组及其消费者：shell、抽屉、标题、列表、图表、新闻、modals、bottom bar。
2. 一个组被新 mobile-layout.css 完整覆盖后，才从旧媒体块删除对应规则；暂未迁移的组继续保留。
3. 搜索 `.mobile-only/.desktop-only`、`@media(max-width:767px)`、`@media(min-width:768px)` 与特定768规则，确定新compact范围的有效结果。
4. 测768、1023、1024两侧的实际computed layout，避免CSS显示手机而JS按桌面处理焦点/手势。
5. 保留主题选择器，只迁结构属性；不得为手机改根全局字体导致桌面一起变大。
6. 不用 `overflow-x:hidden` 隐藏未解决的溢出；发现超宽元素就修它。允许的表格/图表内部滚动要单独列白名单。

手机自选列表与桌面表格共享数据投影。可以按 `isCompactLayout` 条件渲染两种presentation，不能同时初始化两套图表、重复DOM id或重复请求；跨断点时保存状态再切布局。

## 16. 具体测试与操作脚本

### 16.1 自动测试覆盖

- 767、768、1023、1024px范围判断与壳一致；横竖屏切换不留下后台锁。
- 搜索输入、取消、无效代码、当前代码重复选择；只有显式复位才reset图表。
- navigate写入的state不会被watcher清空；返回/前进/外部直接入口/overlay marker均正常。
- 旧排序/分组/时段/主题/指标偏好保持；临时阅读保护不持久化成新的freezeResort。
- `price=0`不因真值判断显示缺失；null/NaN/Infinity不作为有效报价或排序值；时段错配不显示成当前报价。
- 连续选择A/B股票，A晚到响应不能覆盖B；恢复任务可取消，不能把新页滚回旧锚点。
- touch阅读模式不setPointerCapture/preventDefault；展开/桌面操作仍可用；lostpointercapture/pointercancel清理。
