# Market Desk：交易观察体验审查与 Gemini 改进蓝图

审查日期：2026-10-24（北京时间）。对象：当前本地 `inflection-hunter-main` 工作区。交付性质：审查与实施任务书，本轮未修改应用代码、未部署。

## 1. 结论与目标

当前系统已经具备有用的基本结构：总览、分组自选、个股 K 线、板块比较、期权、新闻与日历；这些能力值得保留。影响使用体验的主要原因，是**阅读层级、颜色语义、组件风格和交互状态不统一**。

用户说的“字体扎眼、配色别扭、不丝滑”有具体原因：

1. 关键价格采用 22px / 800，热力图代码采用 20px / 900；同时大量来源、时间、表头和标签只有 9–11.5px。页面既显得用力，又有不少内容难读。
2. 热力图把很小的涨跌也涂成明亮的粉红或薄荷绿，并统一叠白字。颜色先抢走注意力，文字对比却不够。
3. 暗色主题使用深蓝面板、偏白重字、部分浅色实底徽章和偏暗蓝色链接，亮度层级不连续。
4. 上下十张行情卡、长导航、左侧自选、可展开的右侧自选、独立自选页面和说明条同时存在，交易任务的主次不够明确。
5. 页面切换和行情更新没有统一规则；存在脱离真实报价的随机闪烁，以及“冻结排序”状态没有接入排序结果的问题。

还有一类需要先修正的问题：**部分“专业感”由硬编码数据或未经支持的解释构成**，例如固定吞吐量、模拟净买入、现价乘 0.995 的 Gamma 翻转点、人工日内高低区间。这些内容会影响交易判断，优先级高于美化。

本轮改进方向：保留现有灰白 / 深灰、蓝色强调和圆角面板的产品延续性，改成安静、清晰、稳定的美股信息工作台。它应帮助用户完成“判断市场环境 → 比较自选 → 查看个股 → 核查事件 / 期权数据”，不承诺买卖信号或预测收益。

## 4. P1：统一视觉系统

### 4.1 字体：先解决“重字小字混用”，再判断是否换字体

采用一套 UI 字体 + 等宽数字特性。不要全站改成等宽终端字体，也不要继续给每个模块单独指定 JetBrains / 系统 monospace / Segoe / Inter。

推荐默认：`Inter, Segoe UI, PingFang SC, Microsoft YaHei, sans-serif`。如果仓库没有 Inter 字体资源，要么以 Segoe UI 为明确默认，要么本地提供合法许可的 WOFF2 并记录许可；不要只写一个未交付的字体名就声称完成。中文采用系统中文字体。ECharts 使用同一字体族。400 / 500 / 600 为常用层级，700 仅用于极少量标题，数据区取消 800 / 900。

| 内容 | 字号 / 行高 | 字重 | 要求 |
|---|---|---|---|
| 页面标题 | 22 / 30px | 600 | 一页一个主标题，避免口号式副标题 |
| 面板标题 | 15 / 22px | 600 | 不与主价格竞争 |
| 菜单 / 按钮 / 筛选 | 13 / 20px | 500 | 中文常规字距，不压缩 |
| 桌面表格主数据 | 14 / 20px | 400–500 | 价格、涨跌右对齐，启用 tabular-nums |
| 表格代码 | 14 / 20px | 600 | 公司名 12 / 18px、400，最多两层 |
| 大盘卡片价格 | 22 / 28px | 600 | 取消负字距与粗重发亮效果 |
| 个股主价格 | 28 / 34px | 600 | 全页主焦点，仅一个 |
| 来源 / 更新时间 / 标签 | 12 / 18px | 400–500 | 交易相关小字不低于 12px |
| 新闻标题 | 14 / 21px | 500 | 不用全粗、等宽或紧缩字距 |
| 移动端正文与报价 | 14 / 21px | 400–600 | 不整体缩小桌面 UI |

数字启用 `font-variant-numeric: tabular-nums lining-nums`，金额与涨跌列固定宽度；数值更新不改变列宽。中文取消负 letter-spacing。英文代码最多使用 0–0.01em 字距。不要依赖 Windows 上不起统一作用的 font-smoothing 属性解决视觉问题。

禁止用整块高饱和背景表示所有上涨或下跌。普通表格只着色涨跌数字，价格、代码、公司名保持中性色。选中状态是蓝色底 / 边线，不叠加蓝色发光、额外呼吸点、强阴影三套提示。状态点静态即可；休市是中性灰，不是故障红色。

暗色涨跌徽章必须使用暗色 soft 背景，不能继续把浅粉 `#FEE2E2` 和浅绿 `#DCFCE7` 搬过来。颜色的含义是“数值方向”，不要把 VIX 上涨的绿色自动解释成利好。

### 4.3 目前的对比问题有数值依据

按当前源码色值计算，以下是不透明前景 / 背景组合的相对亮度对比；不代表已对所有透明叠层、抗锯齿和状态做完整测试：

| 组合 | 对比度约值 | 问题 |
|---|---:|---|
| `#94A3B8` 在白色上 | 2.56:1 | 小号灰字偏淡 |
| `#10B981` 在白色上 | 2.54:1 | 正收益小字偏淡 |
| `#F43F5E` 在白色上 | 3.67:1 | 负收益小字不足普通文字目标 |
| 白字在 `#34D399` 热力块上 | 1.92:1 | 即使粗体也不能解决 |
| 白字在 `#FB7185` 热力块上 | 2.69:1 | 涨跌百分比和小标签不清晰 |
| `#2563EB` 在 `#131B2E` 上 | 3.32:1 | 暗色小号蓝色链接不足普通文字目标 |

建议颜色中，浅色 up/down 在白底约 5.73 / 5.38；暗色 up/down 在 surface 上约 7.19 / 6.72。对比达标与舒适是两个条件：要同时减小过重字重、控制大面积彩色、保证边界清楚。

验收参考：普通文字至少 4.5:1，大文字至少 3:1；控件可辨识边界与焦点等另行检查。参考 [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/#contrast-minimum)。这里使用它作验收基线，不宣称当前站点或本蓝图已通过认证。

## 5. P1：按交易任务重新组织界面

### 5.1 应用框架与自选入口

### 5.2 市场总览

用户首先要知道“现在是什么交易时段、市场整体怎样、我的股票在哪些方向出现变化”。

- 第一行是简短状态条：纽约日期与 ET 时间、市场时段、源与时效。时钟默认到分钟，秒不是主要任务信息。
- 第一层保留 SPY / QQQ / DIA / IWM / VIX 五个紧凑卡片；ETF 名称清楚说明它们不是指数本体。每卡价格、涨跌、所属时段构成主层；来源时间用统一 12px 次层。

- 热力池名称、实际样本数和面包屑一致。当前 47 自选不能仍写“18 核心标的”。“纳指 100 核心样本”必须显示实际数量，不能暗示完整指数成分覆盖。

### 5.3 热力图：减少信息，强化比较

采用以零为中心、对称阈值的低饱和红灰绿等级，零附近最中性，绝对涨跌越大层级越明显。相同阈值在明暗主题含义一致。建议阈值：≤−3、−3 至−1、−1 至−0.25、−0.25 至+0.25、+0.25 至+1、+1 至+3、≥+3；精确 0 仍显示 0.00%，缺失不进入零档。

起始色阶可使用浅色 `#B45B66 / #D5A4AA / #F0DADD / #EEF1F4 / #DAEBE3 / #A5CDBA / #538E76`，暗色 `#914B59 / #6D3C49 / #432D36 / #252D38 / #243B33 / #305B4B / #3E7B64`。**文字色必须按每个色阶实测选择深字或浅字，不能沿用固定白字。** 这些是待截图验收的建议色阶。

| 格子条件（CSS px，建议起点） | 可显示内容 |

| 宽 ≥140 且高 ≥100 | 代码 18px/600、涨跌 14px/500、价格 12px；最多三行 |
| 宽 ≥80 且高 ≥56 | 代码 14px/600、涨跌 12px |

- Tooltip 包含完整代码、名称、价格、涨跌基准、时间、来源、面积口径。屏幕触摸与键盘必须有等效的列表入口。

### 5.4 自选大表：比较效率优先

- 默认列：代码 / 名称、常规价、常规涨跌%、所选 EXT 价、所选 EXT 涨跌%、数据时间、状态。日内区间在有真实高低价时可选显示；管理操作藏到行菜单。
- EXT 表头写具体时段，例如“盘后价”“盘后涨跌%”，不要只写 EXT。自动模式同时显示正在使用的具体场次及基准。
- 数字右对齐、等宽数字；正常行高 44–48px，紧凑模式 36–40px，用户可切换，正文不随模式变成 10px。
- 表头 sticky；横滚时固定代码列。固定列必须有实底和边界，不能与滚动数字叠字。
- 各种 `—` 不能都叫“无成交”。至少区别：源未覆盖、权限不足、无成交、请求失败、报价过期、该时段未开始。默认简短，详情显示解释与重试。
- 收盘或周末：标“最近常规收盘”；不把数据接收时间呈现为市场更新时间。
- 组标题显示完整名称、数量与等权变化；添加、重命名、删除在菜单中处理。删除组说明是否仅删除分组，移出股票与删除所有分组成员明确区分；支持撤销。
- “全部排行”对 symbol 去重，排序原始数字，缺失 / NaN / Infinity 末尾，同值用稳定 symbol 次序。
- 冻结排序必须冻结 `orderedSymbolIds`，价格继续更新；解除冻结再批量重排。当前 `freezeResort` 仅持久化，`allRankedRows / groupedRows` 仍直接排序，不能只改变按钮文字。
- 鼠标悬停、键盘焦点在表内、选字、拖动滚动条、打开菜单时，暂停行重排。恢复时做一次重排，避免手下目标移动。实际更新最多每秒重排一次。

## 6. P1：动效与操作连续性

“丝滑”的验收目标是位置稳定、反馈及时、上下文保留，而不是动画更多。

| 场景 | 建议规则 | 禁止行为 |
|---|---|---|
| 按钮 hover / pressed | 100–140ms，背景 / 边框轻变 | 整卡跳动、发光扫光 |
| 侧栏展开 / 抽屉 | 160–200ms，最多 8px 平移 + opacity | 弹簧过冲、反复弹跳 |
| 页面切换 | 内容区 120–160ms 淡入；框架不动 | 新旧页面同时占据正常文档流、整页滑上滑下 |
| 真报价更新 | 只高亮变动单元格 350–500ms，浅底逐渐消退 | 随机闪烁、数字滚轮、把日涨跌当逐笔方向 |
| 排序变化 | 稳定 key；允许移动时最多 120–160ms 小位移，批处理 | 阅读/点击时行从鼠标下跑走 |
| 加载 | 保留原布局，局部状态；首次加载使用尺寸匹配 skeleton | 每次刷新清空整屏、骨架反复闪 |
| 错误 | 错误留在对应面板，保留有明确时间的旧数据 | 一个模块失败锁住所有按钮，旧数据冒充新数据 |

具体要求：

1. 删除 `pulseTimer` 驱动的随机行情效果，移除常驻 ping、barShine 和装饰性 pulse。连接状态改变时可给一次短暂反馈。
2. 当前 `<transition>` 没有互斥模式，新旧 keyed 页面会短暂同时存在。采用一个稳定内容插槽：优先简单互斥切换 + 新内容淡入；若使用过渡占位，明确高度和离场定位，不能仅添加更长动画掩盖布局跳变。
3. 不使用 `transition: all` 驱动复杂容器。仅列出 opacity、transform、background-color、border-color 等真正需要的属性。
4. 统一动画时长 token 与曲线，例如 `cubic-bezier(0.2,0,0,1)`；没有必要引入新动画框架。
5. 已有 `prefers-reduced-motion` CSS 是可保留的优点。继续让 JS 行情闪烁 / 列表重排动画尊重同一偏好；保留静态变化标识。
6. 页面切换应有历史记录语义；当前 `history.replaceState` 会覆盖浏览历史。实现可用的前进 / 后退并恢复页面状态，不要让用户从图表“返回”离开整个工作台。
7. 给异步请求明确 symbol / range / request id，旧响应不得覆盖新选择。保留现有请求序号保护，检查所有新增模块是否遵守。
8. 桌面预览面板关闭后焦点回到原股票，完整页面导航后焦点落到标题区域；不要用 autofocus 抢夺持续输入。

## 8. Gemini 的执行顺序与代码边界

### 阶段 A：锁定基线、修正可信度

1. 先看 `git status` 和当前 diff。工作区已有用户/其他工具修改，禁止 reset、checkout 覆盖或整文件回退。
2. 阅读本蓝图和实际最新源码，用函数 / 组件名称定位，不依赖可能已变化的行号。复核 T01–T12，逐项修正；把尚未有真实数据的内容改成明确空态。
3. 不接 IBKR / TWS / IB Gateway；不扩建数据服务或购买 API 来替代本轮 UI 修正。真实源升级另列后续任务。
4. 使用带来源/时间/状态的 display model 汇总 UI 字段，避免每个页面自己默认 `0 / 100`。

## 9. 最终验收清单

### 视觉验收

- [ ] 总览 / 自选 / 个股 / 期权 / 新闻 / 财报使用同一字体层级、涨跌色和状态组件。
- [ ] 主要价格不再使用 800 / 900；业务说明与数据时间至少 12px，表格主数值 14px 左右。
- [ ] 浅色红绿文字、暗色蓝字、热力图每档文字均通过对应对比核验；不能以截图看着舒服代替计算。
- [ ] 暗色没有浅粉浅绿实底“贴纸”，无常驻发光与呼吸装饰。
- [ ] 1440 和 1920 宽度下关键代码 / 价格 / 涨跌完整；小热力块按信息等级隐藏，不出现大量 `M… / +2…`。
- [ ] 390px 下品牌不溢出、导航不挤成七小格、首屏能开始核心任务；完整表格横滚时能保持代码身份。

### 数据呈现验收

- [ ] 页面无固定“1,420 事件 / ≤1s / 假 Bloomberg Reuters OK / 假 L2 已就绪”。
- [ ] 无固定净流入、人工 Gamma flip、人工 ±1.5% 日内区间、生产随机 OHLCV。
- [ ] 缺失、0、过期、无权限、未覆盖与休市明确区分；真实数值始终保留来源和有效时段。
- [ ] 收盘数据接收时间与源时间分别呈现；刷接口不刷新成交时间。
- [ ] 组均值对排序不敏感，全部排行去重，缺失始终末尾。
- [ ] 热力图和表格在同一批报价到达后同步更新，不靠切主题触发。
- [ ] 静态日历有真实来源 / 核验日期或明确待核验，不冒充官方实时服务。

### 操作与动效验收

- [ ] 冻结时行顺序保持、数值继续更新；鼠标悬停 / 焦点 / 菜单期间不重排。
- [ ] 10 次连续页面切换不出现两个内容页撑高、空白闪回、残留图表、失效按钮。
- [ ] 连续切换三个 symbol，只有最终 symbol 的结果进入当前图表 / 期权 / 新闻。
- [ ] 返回能恢复原列表位置、分组、排序、选中项；主题切换不丢图表缩放。
- [ ] 弹窗 / 抽屉键盘可进入、可退出、焦点可返回；减少动效时无非必要位移。
- [ ] 无报价变化 30 秒没有红绿随机闪动；有真实变化只高亮对应值。
- [ ] 单模块加载失败可重试，其他模块继续使用；无永久“刷新中”。

成功标准：用户可以用更少的视线移动认出“标的、价格、变化、场次、时间、可否信任”，连续看一段时间不会被颜色、字重、无意义闪动和重复控件打断。是否达到这一点，需要对实现后的页面重新截图和实际操作验收，不能只以修改 CSS 或测试通过宣布完成。
