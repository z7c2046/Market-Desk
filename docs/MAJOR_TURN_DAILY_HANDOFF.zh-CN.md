# SNDK / MU 日线重要顶底识别：Gemini / AntiGravity 实施说明

日期：2026-10-19。本文是设计交接，不是已实现功能，也不是经过真实行情验证的策略。所有新增数值均为首轮对照实验的基线，不能称为最优参数或命中概率。

## 1. 目标与当前代码的关系

用户要识别的是明显上涨后的高位衰竭、明显下跌后的恐慌放量止跌。以 SNDK、MU 为首批验证标的，只用已完成日线；主要观察信号之后 5 / 10 / 20 个交易日。背景可以使用过去几个月的日线，不引入周线硬性条件。

当前代码已有 swing_pulse_v1，包括整理启动、普通放量突破、均线回调、独立转弱和 ATR 退出。2026-10-19 本次读取的文件中，已经出现 RSI 基准入口隔离、风险线集中处理、基准缺失返回 unknown、评估传入日期区间等修正；本文不把上一轮缺陷清单当作当前所有缺陷仍然存在的证明，也未重新验收这些修正。

新增独立算法 major_turn_v1，不继续把新逻辑塞入现有大函数，不删除或重定义旧算法。新模式只允许以下两类形态：

- panic_bottom：恐慌放量后的底部恢复。
- exhaustion_top：明显上涨后的高位缩量、动能衰减。

普通突破、普通回调、单独均线交叉、普通 ATR 止损不得作为该模式的顶底信号。风险管理与形态识别分开；未持仓也应能看到顶部事件。不要强制 B、S 交替来制造整齐的图形。

## 2. 指标、数据与计算约定

所有窗口长度单位都是交易日。t 表示当前已完成日线；O/H/L/C/V 为开高低收与成交量；下标区间两端均包含。

| 名称 | 精确定义 |
| --- | --- |
| R[t] | Wilder RSI(14) |
| A[t] | Wilder ATR(14)，用于上下文门槛时取 ATR[t-1]，不让恐慌当天大振幅即时抬高自身判断尺度 |
| RVOL[t] | V[t] / mean(V[t-20 ... t-1]) |
| VP95[t] | 此前120日成交量的95%分位，排除 t；统一使用 nearest-rank，升序后取 ceil(0.95*n)-1 |
| HH60[t] / LL60[t] | max(H[t-59 ... t]) / min(L[t-59 ... t]) |
| HC60[t] | max(C[t-59 ... t]) |
| RMAX20[t] | max(R[t-19 ... t]) |
| VDECAY[t] | mean(V[t-2 ... t]) / mean(V[t-22 ... t-3])；分母与最近三天完全不重叠 |
| CLV[t] | (C[t]-L[t]) / (H[t]-L[t])；零振幅时取0.5，只作证据字段 |

每个检测日必须已经具备180根有效日线；必须在逐根循环中检查预热资格，不能只检查传入数组的总长度。缺失、NaN、ATR<=0、相关窗口缺量时，跳过依赖该指标的检测，并记录 dataQuality。

禁止 Number(null) 后再用 Number.isFinite 当作有效值检查。缺失量不能补成真实零量参与分位。统一复权 OHLC 与拆股量口径，证券身份不得跨重组、退市重上市随意拼接。美股日线按交易所日期和实际收盘时间判定完成，包含提前收市安排。

QQQ / SMH 在第一版只提供环境标签，不作为硬性放行条件。重要底部可能正发生在板块弱势时，重要顶部也可能出现于板块仍强时。缺失基准显示 unknown，不补造成强弱。

## 3. 底部：先出现极端事件，再验证价格恢复

### 3.1 底部观察日 t0

同时满足以下条件才建立候选：

1. (HC60[t0] - C[t0]) / A[t0] >= 4：已经有明显回撤。
2. C[t0] < C[t0-5]：近期仍在下跌，而非普通上涨放量。
3. R[t0] <= 30。
4. RVOL[t0] >= 2.0，且 V[t0] >= VP95[t0]：同时要求相对均量放大和历史稀有量。
5. L[t0] <= min(L[t0-20 ... t0-1]) + 0.25*A[t0]：接近近期低点。

这里不要求价格走出两个低点，不要求标准 RSI 底背离，也不强制当天为阴线。巨量、超卖只能建立观察，不能命名为“聪明钱已买入”。

在 t0 收盘冻结：L0、H0、C0、R0、A0=A[t0]；其中 A0 是 t0 前一天的 Wilder ATR。

- invalidationLevel = L0 - 0.5*A0。
- recoveryLevel = L0 + 0.60*(H0-L0)。
- confirmationDeadline = t0+7。

保留当天实体、下影线、CLV、RVOL和量分位作为证据，但第一版不要再增加影线比例硬门槛。

### 3.2 底部确认

只在 t0+1 至 t0+7 的已完成日线上确认。对每根 t，先检查失效，再检查以下条件同时成立：

- C[t] > recoveryLevel：已经收复恐慌日振幅的60%以上。
- C[t] > H[t-1]：当天收盘越过前一天高点。
- R[t] >= R0+4，且 R[t] > R[t-1]：动能实际恢复。

候选建立后至确认日，任何日线 L[t] < invalidationLevel，都先判为 invalidated，当天不能再确认。容许 L0 下方0.5*A0以内的测试，但不允许继续把失效价下移。等于阈值时不视为跌破。

正式确认不要求 RSI 已经回到30以上，避免把超卖区内的早期恢复一律排除。t0 当天仅观察；这意味着第一版不会宣称在恐慌日收盘就确认最低点。

满足恢复条件时，如果 (C[t]-L0)/A0 > 2.0，仍记录真实确认事实，但标记 timing=late、actionable=false，不显示成及时的底部买点。不能把确认日期移回 t0。

到 t0+7，按“失效 > 确认 > 到期”顺序处理；到期未确认则 expired。

### 3.3 暂不同时加入多套确认方法

首版只测试上述恢复确认。若后续要增加“反弹后缩量回踩确认”，另建 detectorVersion 或独立子分支，先冻结回踩锚点，再等待之后的收盘突破，不能将最漂亮的事后回踩挑出来替换原结果。

## 4. 顶部：高位背景、动能回落与量能衰减共同成立

### 4.1 顶部观察日 d

以下条件同时成立：

1. C[d] > SMA50[d]，且 (C[d]-LL60[d])/A[d] >= 6：当前位置仍处于一轮明显上涨之后。
2. HH60[d]-C[d] <= 1.5*A[d]：价格仍接近高位，不能在大跌很久后才称为顶部观察。
3. RMAX20[d] >= 70：最近20天曾经明显超买。
4. R[d] <= RMAX20[d]-5：现在动能已经回落，而非仍在同步增强。
5. VDECAY[d] <= 0.80：最近三日均量低于此前独立20日均量至少20%。

这是一套“高位动能衰减”假设，不等同于标准顶背离。它不强制价格第二次创新高，不要求 R[d] 仍然>=70，也不要求等待右侧两根 pivot 才能发出观察。

标准顶背离可以作为额外证据，但只允许使用当时已经确认的历史 pivot，且不得改变本版核心触发条件。

在观察日冻结：

- peakPrice = HH60[d]，peakTime 取该窗口最高价第一次出现的日期；这是参考锚点，不是信号日期。
- A0 = A[d]。
- triggerLevel = min(L[d-3 ... d-1])，排除观察日。
- invalidationLevel = peakPrice + 0.5*A0。
- confirmationDeadline = d+7。

如果只是缩量，但 RSI 继续走强，就不发顶部观察。该分支专门研究缩量衰竭，无法覆盖所有放量派发或消息跳空顶部，不能宣称全覆盖。

### 4.2 顶部确认

观察日 d 至 d+7，收盘 C[t] < triggerLevel，且 R[t] < R[t-1]，确认顶部转弱。

若 C[t] > invalidationLevel，先判为 invalidated；不要因为原先发出过预警就坚持顶部判断。收盘等于阈值不算突破。到期处理顺序同底部。

同一根日线若首次同时满足观察和确认，事件日志保留两条状态变化，但通知与主图只展示一次“顶部确认”，并标记 leadBars=0。

若 (peakPrice-C[t])/A0 > 2.0，记录 timing=late、actionable=false。确认太晚仍是真实结果，应计入延迟，不得回画成提前预警。

## 5. 稀疏信号：按事件去重，不靠强行买卖交替

使用 episodeId 表示同一轮高位衰竭或恐慌下跌；attemptId 表示其中一次冻结锚点的候选。两个方向分别维护状态。

第一版采用如下确定规则：

1. 同一方向同时最多一个活动 attempt；episode 从首次观察日开始，固定覆盖20根日线（e0至e0+19），期限不随更新向后滚动。
2. 同一 episode 最多推送一次观察、一次确认。普通日线波动只更新证据，不重新生成 eB/eS。
3. attempt 失效或到期后，至少间隔两根日线，且再次满足全部初始条件，才允许同 episode 内创建新 attempt。底部新低还须低于旧 L0 至少1个旧 A0；顶部新高须高于旧 peakPrice 至少1个旧 A0。新锚点与旧锚点分开，旧事件不改写。
4. 内部新 attempt 记录 candidate_created，但不再次推送观察；若后来确认，可推送该 episode 唯一一次确认，并展示最终使用的 attempt 锚点。
5. attempt 最长确认期不得超过 episode 末日。同 episode 一经确认，不再产生第二次确认，之后记录 outcome，不反向修改确认事实。
6. episode 结束后，同方向重新建立 episode，除完整触发条件外，还需要发生过连续三日 RSI 中性恢复（底部>=45；顶部<=55），或价格形成超出旧极值至少2个旧 A0的新一轮极端。新极端例外用于避免长时间超卖时永远不再检测。
7. 每天都继续计算失效和风险，不因通知去重而停止计算。

上述20根、两根、1/2 ATR和中性恢复阈值也属于待验证基线。专门报告因此合并、推迟或漏掉的事件；不能通过大量屏蔽信号让命中率表面提高。

## 6. 状态、输出与不重绘

attempt 状态转换：candidate -> confirmed / invalidated / expired。confirmed 之后的失败写入独立 outcome，不能删除确认。记录不可变事件流，activeSetups 是截至当前日重建的视图。

最小输出字段：algorithm、algorithmVersion、configHash、symbol、episodeId、attemptId、kind、eventType、eventAt、anchorAt、detectedAt、confirmedAt、stage、direction、triggerLevel、invalidationLevel、frozenAtr、timing、actionable、evidence、dataQuality。

- eventAt 与 signal.time 必须是该事件真实可知日期。
- detectedAt 记录观察建立日，confirmedAt 记录价格条件确认日；anchorAt仅用于解释参考高低点。
- evidence 深拷贝；后来新增承接证据不能污染观察当天的 evidence。
- 对每个截断日 t，单独运行截至 t 的数据，事件流应与全量运行中 eventAt<=t 的事件相同。比较不可变事件，不比较被后续演变修改的最终状态对象。
- 图表上可以有参考锚点，但可交易信号只能画在 eventAt，不能移到历史最高/最低的那根K线。
- 内部可通过 adapter 映射 eB/B/eS/S以兼容旧图表；界面显示“底部观察、底部确认、顶部观察、顶部确认”，不把所有 B/S 混成一种原因。
- late 确认单列展示；actionable=false 只影响试验交易策略，不影响事件记录与失败统计。

## 8. 验证要求：先检查顶底识别，再看交易收益

### 8.1 事件评估

分别统计观察和确认、顶部和底部、及时和晚确认：

- 每只股票每月观察次数、确认次数、失效比例及覆盖的独立事件数。
- 完整5/10/20日窗口的 MFE/MAE，全部截断到>=0；不完整窗口列 pending，不纳入对应分母。
- 顺序结果：从事件日收盘为参考，未来有利方向达到3个冻结 ATR，是否先于触及该 attempt 的冻结失效位；阈值保持一致，不以“百分比或ATR取容易达标者”偷偷降低目标。
- 同日高低同时触及两界，日线无法确定顺序，列 ambiguous；单独报告，保守策略可按失败，不能按成功。
- 重大转折覆盖率：在冻结的价格数据上独立建立参考转折事件，再与信号做一对一匹配，不能仅从已经发出信号的日期挑转折。参考标签可以事后使用未来数据，但必须标为 evaluation-only，禁止输入检测器。
- 记录参考极值与实际观察/确认日期之间的时间差，以及价格差/冻结ATR。提前和滞后分别报告，不只给正负相抵的平均数。
- 同一段30日上涨或下跌不得拆成多次“抓到重大转折”。匹配窗口与重大转折标签规则需在样本外检验前冻结；人工参考标注不得拿来反复调门槛。
- 评估区间前的数据仅供指标预热。事件时间在所选区间内、且未来窗口完整落在区间内，才进入该窗口的统计。

### 8.2 交易对照

先评估提示价值，再用同一组确认事件模拟只做多/现金，候选不交易，下一有效交易日开盘成交，加入手续费和滑点。及时确认与晚确认分别做可审计对照；默认 actionable=false 不触发试验交易。隔夜跳空不得按信号日收盘或理想止损价格成交。

顶底提示不是完整风险管理系统。如果另加 ATR 风控，必须命名为独立策略变体，并输出退出原因；不能把 ATR 退出记成“成功预测顶部”。

### 8.3 SNDK / MU 样本要求

用户描述的4月、6月末、7月末行情属于待核对的案例线索，本次没有逐日验证实际价量，不得写成已验证正例。对齐具体交易日期后，记录当日已知的 RSI、RVOL、量分位、背景涨跌幅及事件时间。

至少同时纳入：巨量超卖后继续跌；超买缩量后继续涨；V形恢复但无底背离；没有异常量的普通回调；单次消息跳空；顶部已下跌很多才确认。不能只挑三个成功案例。

SNDK、MU先使用同一组参数，不分别拟合这几次顶底。按时间切分开发/样本外区间；因样本外结果再次调参，就需要新的未使用区间。历史长度不足需明确报告，不能编造更早历史或胜率。

## 9. 必须补充的验收测试

1. RSI超卖但无异常量：无恐慌底观察；巨量但无明显回撤：无恐慌底观察。
2. 巨量超卖当天只观察；次日满足恢复条件可确认；不要求标准底背离或RSI已上穿30。
3. 继续破低先失效，同根日线反弹也不能绕过失效；旧失效价不能下移。
4. 缩量上涨但RSI继续增强：无顶部观察；曾超买后跌回65且其余条件满足：允许顶部观察。
5. 顶部先观察，再跌破冻结支撑确认；持续突破冻结失效位则失效。
6. 同一episode连续多天符合条件，只通知一次观察、一次确认；内部新attempt不能改写旧锚点。
7. 普通突破、均线回调、ATR退出不得出现在 major_turn_v1 的顶底事件中。
8. 所有历史截断点的事件前缀一致；观察证据不被未来状态修改；改变未来数据不影响过去事件。
9. 指标预热不足、缺量、缺基准、拆股调整异常不得生成伪信号；基准unknown不阻止个股检测。
10. 只剩1天后续数据不进入20日统计；先失效后大涨不算顺序命中；同日双触及必须可见。
11. 图表、扫描、回测使用相同算法版本与配置；每个可调参数有验证其实际生效的测试。
12. 保留旧算法固定样本快照，新增模式不得改变旧基准输出。

首轮交付应包含代码、以上测试、SNDK/MU逐事件核对表和参数清单。先报告反例与遗漏，再报告收益；不得承诺精准命中绝对最高最低点。

## 10. 方法依据与边界

RSI在强趋势中可以长期停留于超买/超卖，因此极值只作背景，必须结合价格变化。来源：[Fidelity RSI](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/RSI)。

恐慌量、价格反应与后续测试的思路参考威科夫分析。来源：[Wyckoff Analytics](https://www.wyckoffanalytics.com/wyckoff-method/)。这不证明日线数据能识别交易者身份，也不证明本说明提出的阈值有预测优势。本文所有具体数值、状态规则和验收标准均为本项目提出的待验证设计。
